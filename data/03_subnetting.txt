Subnetting และการวางแผนเครือข่าย

Subnetting คือการแบ่ง IP Network ขนาดใหญ่เป็นเครือข่ายย่อย เพื่อแยก Broadcast Domain จัดสรร Address ให้เหมาะกับจำนวนอุปกรณ์ เพิ่มความปลอดภัย และทำให้การบริหารเส้นทางเป็นระบบ Prefix Length ระบุจำนวนบิตของ Network เช่น /24 เท่ากับ Subnet Mask 255.255.255.0 ส่วนบิตที่เหลือใช้ระบุ Host

สูตรพื้นฐานของ IPv4 คือจำนวน Address ทั้งหมดต่อ Subnet เท่ากับ 2 ยกกำลังจำนวน Host Bits โดยเครือข่ายทั่วไปหัก Network Address และ Broadcast Address อย่างละหนึ่ง ตัวอย่าง /26 เหลือ Host Bits 6 บิต มี 64 Address และใช้กับ Host ได้ 62 Address ขนาด Block คือ 64 จึงแบ่ง /24 เป็นช่วง .0-.63, .64-.127, .128-.191 และ .192-.255

ตัวอย่าง 192.168.10.70/26 อยู่ใน Subnet 192.168.10.64/26 เพราะช่วงเพิ่มทีละ 64 Network Address คือ 192.168.10.64 Broadcast Address คือ 192.168.10.127 และ Host ที่ใช้งานได้คือ 192.168.10.65 ถึง 192.168.10.126 หากต้องการหา Block Size จาก Subnet Mask ให้ดู Octet ที่แบ่ง Subnet แล้วคำนวณ 256 ลบค่าของ Octet นั้น เช่น 255.255.255.192 ได้ 256-192 เท่ากับ 64

ตารางที่ควรจำ: /24 มี 256 Address ใช้ได้ 254, /25 มี 128 ใช้ได้ 126, /26 มี 64 ใช้ได้ 62, /27 มี 32 ใช้ได้ 30, /28 มี 16 ใช้ได้ 14, /29 มี 8 ใช้ได้ 6 และ /30 มี 4 ใช้ได้ 2 ในลิงก์ Point-to-point อาจมีการใช้ /31 ตามมาตรฐานที่รองรับ จึงไม่ควรนำสูตรหักสองไปใช้กับทุกกรณีโดยไม่ตรวจบริบท

ขั้นตอนทำโจทย์ Subnetting: 1) แปลง Prefix เป็น Mask 2) หาจำนวน Host Bits 3) คำนวณ Block Size 4) หา Network ที่ครอบคลุม IP ที่โจทย์ให้ 5) หา Broadcast ก่อน Network ถัดไปหนึ่งค่า 6) ระบุช่วง Host ระหว่าง Network กับ Broadcast 7) ตรวจว่าจำนวน Host เพียงพอ

VLSM หรือ Variable Length Subnet Mask ใช้ Prefix หลายขนาดในเครือข่ายเดียวเพื่อประหยัด Address วิธีวางแผนคือเรียงเครือข่ายจากจำนวน Host มากไปน้อย เลือก Block ที่เล็กที่สุดแต่รองรับจำนวน Host ได้ แล้วจัดสรรต่อเนื่องโดยไม่ให้ช่วงทับกัน ตัวอย่างแผนก 100 เครื่องใช้ /25 แผนก 50 เครื่องใช้ /26 และแผนก 20 เครื่องใช้ /27

Route Summarization คือการรวมหลาย Route ที่ต่อเนื่องกันเป็น Prefix เดียว ลดขนาด Routing Table แต่ต้องมีบิตส่วนหน้าร่วมกันและช่วงต้องตรงขอบเขต ตัวอย่าง 192.168.0.0/24 ถึง 192.168.3.0/24 รวมเป็น 192.168.0.0/22 ได้ การสรุป Route ที่กว้างเกินจริงอาจส่ง Traffic ไปผิดทาง

ข้อผิดพลาดที่พบบ่อยคือใช้ Network หรือ Broadcast เป็น Host, เลือก Gateway อยู่นอก Subnet, คิดจำนวน Host โดยไม่เผื่อ Gateway และอุปกรณ์โครงสร้างพื้นฐาน และกำหนด Subnet ทับกัน การออกแบบควรเผื่อการเติบโต บันทึก VLAN, Prefix, Gateway, DHCP Range และ Reservation ให้ตรวจสอบได้

FLSM และ VLSM ต่างกันอย่างไร

FLSM หรือ Fixed Length Subnet Mask แบ่งทุก Subnet ให้มี Prefix เท่ากัน ข้อดีคือคำนวณง่ายและรูปแบบสม่ำเสมอ แต่ถ้าแต่ละแผนกมีจำนวน Host ต่างกันมากจะสิ้นเปลือง Address ตัวอย่างแบ่ง 192.168.10.0/24 เป็นสี่ Subnet แบบ /26 ทุกแผนกจะได้ 62 Usable Hosts เท่ากัน

VLSM หรือ Variable Length Subnet Mask เลือก Prefix ตามจำนวน Host ของแต่ละเครือข่าย จึงประหยัด Address มากกว่า ขั้นตอนสำคัญคือต้องจัดสรรจากความต้องการที่มากที่สุดก่อน และทุก Block ต้องเริ่มที่ขอบเขตที่หารด้วย Block Size ลงตัว

ตัวอย่างคำนวณ /27 แบบละเอียด

โจทย์กำหนด IP 192.168.50.77/27 ค่า /27 เท่ากับ Mask 255.255.255.224 เหลือ Host Bits 5 บิต จึงมี Address ทั้งหมด 2^5 = 32 ค่า และใช้งานกับ Host ทั่วไปได้ 30 ค่า Block Size คือ 256-224 = 32 ช่วง Subnet จึงเริ่มที่ .0, .32, .64, .96 และเพิ่มทีละ 32

IP .77 อยู่ในช่วง .64-.95 ดังนั้น Network Address คือ 192.168.50.64, Broadcast Address คือ 192.168.50.95 และ Usable Host คือ 192.168.50.65-192.168.50.94 หากกำหนด Gateway เป็น 192.168.50.65 ยังเหลือ Address อื่นให้ Client ได้ 29 ค่า

ตัวอย่างคำนวณ /28

Prefix /28 เท่ากับ Mask 255.255.255.240 เหลือ Host Bits 4 บิต มี 16 Address และใช้กับ Host ได้ 14 ค่า Block Size คือ 16 ตัวอย่าง 10.10.10.140/28 อยู่ในช่วง 10.10.10.128-143 จึงมี Network 10.10.10.128, Broadcast 10.10.10.143 และ Usable Host 10.10.10.129-142

ตัวอย่างแบ่งเครือข่ายให้หลายแผนกด้วย VLSM

มีเครือข่าย 192.168.100.0/24 และต้องรองรับแผนก A 100 เครื่อง, แผนก B 50 เครื่อง, แผนก C 25 เครื่อง และลิงก์ Router 2 เครื่อง สามารถวางแผนได้ดังนี้:

- แผนก A ใช้ 192.168.100.0/25 มี Usable Host 126 ค่า
- แผนก B ใช้ 192.168.100.128/26 มี Usable Host 62 ค่า
- แผนก C ใช้ 192.168.100.192/27 มี Usable Host 30 ค่า
- ลิงก์ Router ใช้ 192.168.100.224/30 มี Usable Host 2 ค่า

ช่วง 192.168.100.228-255 ยังเหลือสำหรับการขยาย แต่ต้องแบ่งต่อให้ตรงขอบเขต Prefix การวางแผนควรบันทึก Network, Mask, Gateway, DHCP Range และ VLAN ของแต่ละแผนก

ขั้นตอนทำโจทย์ Subnetting ฉบับใช้งาน

1. อ่านจำนวน Host ที่ต้องการและเผื่อ Gateway หรืออุปกรณ์โครงสร้างพื้นฐาน
2. หา Host Bits ที่ทำให้ `2^Host Bits - 2` เพียงพอ
3. หา Prefix จาก `32 - Host Bits`
4. แปลง Prefix เป็น Subnet Mask
5. คำนวณ Block Size จาก 256 ลบค่า Mask ใน Octet ที่แบ่ง Subnet
6. หา Network Address โดยเลือกขอบเขต Block ที่ครอบคลุม IP
7. หา Broadcast ก่อน Network ถัดไปหนึ่งค่า
8. ระบุ Usable Host ตั้งแต่ Network+1 ถึง Broadcast-1
9. ตรวจว่าช่วงไม่ทับกับ Subnet อื่นและจำนวน Host เพียงพอ

ข้อผิดพลาดที่พบบ่อยและวิธีตรวจ

- ลืมหัก Network กับ Broadcast ทำให้ประเมิน Host มากเกินจริง
- เริ่ม VLSM ที่ Address ซึ่งไม่ตรง Block Boundary ทำให้ Subnet ทับกัน
- เลือก Prefix เล็กเกินไป เช่น ใช้ /28 กับ 20 Hosts ทั้งที่รองรับได้เพียง 14
- กำหนด Gateway เป็น Network Address หรือ Broadcast Address
- สับสนระหว่างจำนวน Subnet กับจำนวน Host Bits ควรเขียนเลขฐานสองหรือ Block Table ช่วยตรวจ

สรุป Prefix ที่ใช้บ่อย

- /24: 256 Address, 254 Usable, Block Size 256
- /25: 128 Address, 126 Usable, Block Size 128
- /26: 64 Address, 62 Usable, Block Size 64
- /27: 32 Address, 30 Usable, Block Size 32
- /28: 16 Address, 14 Usable, Block Size 16
- /29: 8 Address, 6 Usable, Block Size 8
- /30: 4 Address, 2 Usable, Block Size 4
